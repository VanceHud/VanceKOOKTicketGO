# KOOK 机器人稳定性/效率优化 + 网页端工单特殊信息渲染优化

已核对 KOOK 官方文档（developer.kookapp.cn 的 websocket / rate-limit / kmarkdown / cardmessage 页面）并通读相关代码。网关的 resume、心跳 30s/6s、s=5 清会话、退避上限 60s、`X-Rate-Limit-*` 响应头、自身消息过滤均与文档一致；以下为确认的差距与问题。

## 一、机器人稳定性与效率（Go）

### 1. 网关事件 sn 去重 — `internal/kook/gateway.go`
官方文档明确「已经处理过的 sn，直接抛弃不处理」，且平台会按 PING 上报的 sn 重传其后消息（可能含已处理事件）。当前 `serve()` 的 SignalEvent 分支无条件调用 OnEvent，平台重传会导致事件被重复处理（重复归档、重复按钮动作）。
- 维护「已受理 sn」环形窗口（map + 最近 512 个的淘汰队列）；收到事件帧时 sn 在窗口内 → 计数 `eventsDuplicated` 并跳过（不调 OnEvent、不推进 sn）。
- 乱序取舍：sn ≤ lastSN 但不在窗口内（乱序迟到的新事件）仍处理，行为与现状一致，注释说明。
- `GatewayStatus` 增加 `EventsDuplicated` 字段（omitempty，向后兼容）。

### 2. 心跳 ±5s 抖动 — `internal/kook/gateway.go`
文档要求「每隔 30s（随机 -5~+5）」，当前为固定 30s。`heartbeatLoop` 的 ticker 改为逐轮 `time.NewTimer(interval + jitter)`，抖动幅度 = min(5s, interval/6)（兼容测试中的小间隔配置）。

### 3. 读循环卸载同步 SQLite 写 — `internal/kook/gateway.go`
`persistSessionSoon` 去抖到期时在读循环内同步执行 `SaveGatewaySession`（busy_timeout 5s），消息风暴时可能阻塞读循环数秒、挤占 6s PongTimeout → 心跳误判重连。
- `persistSessionSoon` 只置脏标记并唤醒 `persistLoop`（新增带缓冲的唤醒 channel）；所有落库由 persistLoop 协程执行（2s tick + 唤醒）。`serve()` 退出的 `defer persistSession()` 保留（已离开读循环）。

### 4. 429 惩罚分桶化 — `internal/kook/api.go` + `ratelimit.go`
当前任何桶的 429 都触发全局 `penalize()`（清零全局令牌 + 全局速率减半最长 30s），非关键接口被限流会拖慢全部工单关键调用。文档语义：`X-Rate-Limit-Global` 才代表触犯全局限制。
- `call()` 中 429 仅当 `info.global` 为真（或响应无桶信息）才调用 `penalize()`；桶级 429 交给 `observe()` 已记录的 remaining=0/resetAt 排队，退避等待逻辑不变。

### 5. 幂等端点瞬态重试 — `internal/kook/api.go`
当前仅 429 重试，网络错误/5xx 一次失败即返回（如 user/view 失败会误判权限）。
- 幂等集合：所有 GET + POST 中 `guild-role/grant|revoke`、`channel-role/update`、`message/update|delete`、`direct-message/update|delete`、`game/update`、`game/delete-activity`、`user/offline`（重复调用无副作用）。
- 这些端点遇网络错误或 HTTP ≥500 时按 500ms×attempt 退避重试（计入现有 maxAttempts=3，ctx 取消不重试）；创建类（message/create、channel/create、game/create、game/activity 等）不自动重试，避免重复发送/重复建频道。

### 6. 事件分片扩容 — `internal/bot/dispatch.go`
`eventShards` 4 → 16：单个 openTicket（90s 上限）串行化同分片频道的概率从 1/4 降到 1/16，缓解队头阻塞。队列容量 128 不变。

### 7. enqueueEvent 回退修复 — `internal/bot/bot.go:173-183`
dispatcher 为 nil 时不再同步 `handleEvent`（会把网关读循环堵最长 90s）：改为 `log.Error` + 返回 false（拒收 → 网关保序重连续传）。

### 8. 限流速率配置接通 — `internal/config/config.go` + `cmd/server/main.go`
`bot.Config.RatePerSecond/RateBurst` 目前是死旋钮（runtimeConfigProvider 从不填充）。新增环境变量 `KOOK_RATE_PER_SECOND`、`KOOK_RATE_BURST`（默认 0 = 内置 8/s、burst 4，多实例部署可各自调节），runtimeConfigProvider 填入；修正 `api.go:35`、`bot.go` 中「默认 4/s」的过时注释。

### 9. 顺手小修
- PONG 陈旧遮蔽：`pongCh` 携带心跳代数，heartbeatLoop 只接受当前代数的 PONG。
- `ttlCache.set` 全表扫描限频（`internal/bot/bot.go`）：到期扫描最多 30s 一次，仅容量满时立即扫。

## 二、网页端工单特殊信息渲染（web/frontend）

### 10. 倒计时崩溃修复 — `components/KookCardView.tsx` + `lib/format.ts`
`new Date(module.endTime).toISOString()` 对非法值抛 RangeError，仅顶层 ErrorBoundary 兜底 → 整页白屏（卡片 JSON 来自用户消息原样入库）。
- 安全解析：Number.isFinite；数值 < 1e11 视为秒级时间戳 ×1000；年份落在 2001–2100 之外视为非法，回退 `t("ticket.countdown")`。
- `format.ts` 的 `getFullYear() < 1970` 过滤改为 `< 2001`（修 1970-01-xx 误判）。

### 11. KMarkdown 渲染器补齐 — `lib/kmarkdown.ts`（对齐官方文档）
- **修复引用块丢失 bug**：`blocks.push(\`\`)` 推空字符串导致引用文字直接消失 → 渲染 `<blockquote>`（previewStyles 中 blockquote 样式已存在但从未被用到）。
- `---` 独立行 → `<hr/>`（官方支持；与列表正则 `^\s*[-*+]\s+` 不冲突）。
- `(spl)内容(spl)` 剧透 → `<span class="mdk-spoiler" tabindex="0">`；`KMarkdownPreview` 容器加事件委托 onClick 切换 revealed class（点击揭示，对齐 KOOK 客户端交互），previewStyles 加模糊/揭示样式。
- `(font)内容(font)[theme]` 主题色 → `<span class="mdk-font-{theme}">`，theme 覆盖官方全集 primary/success/danger/warning/info/secondary/body/tips/pink/purple，映射 Tailwind 文本色。
- 行内代码占位符碰撞修复：占位符加每次调用随机前缀，避免用户文本恰含 `\uE000` 序列时错乱。
- `\` 转义（官方支持）：escapeHtml 后把 `\` + 特殊字符（`* ~ \` [ ] ( )`）暂存为占位，标记处理后还原为字面字符。
- 新增测试 `web/frontend/tests/kmarkdown.test.mjs`（node --test）：引用、分隔线、剧透、font、转义、占位符碰撞、XSS 回归。

### 12. paragraph 逐字段渲染 — `lib/kookcard.ts` + `KookCardView.tsx`
新增 `fieldsOf()`：paragraph 逐字段返回 {content, markdown}；RichText 逐字段渲染（kmarkdown 字段用 KMarkdownPreview，plain 字段按纯文本），不再因任一字段是 kmarkdown 就整块按 markdown 解析（避免 plain 字段的 `*` `[` 被误格式化）。`textOf` 保留兼容其他调用点。

### 13. 空段落与未知模块占位
- `KMarkdownPreview.tsx`：emptyText 为空字符串时返回 null（消除卡片 section 内空 `<p>` 残行）。
- `KookCardView.tsx` default 分支：渲染「不支持的卡片模块」小字占位（新增 i18n key），不再无声消失。

### 14. 卡片 color 校验 — `KookCardView.tsx`
`borderColor` 仅当匹配 `/^#([0-9a-fA-F]{3}|[0-9a-fA-F]{6}|[0-9a-fA-F]{8})$/` 时应用。

### 15. 时间线自动滚动修复 — `routes/TicketDetail.tsx`
现状：`scrollIntoView({block:"end"})` 滚动所有可滚动祖先（整个页面被拽走）；SSE 触发 refetch 后用户在上方阅读也被强拉到底部。
- 通过 `closest('[data-radix-scroll-area-viewport]')` 拿到真实滚动容器；原生 scroll 监听记录「距底 < 80px」为贴底（存 ref 不触发重渲染）；messageCount 变化时仅贴底或首次加载才 `viewport.scrollTop = scrollHeight`；移除 scrollIntoView。

## 明确排除（后续迭代可选）
- HTML/CSV 导出的卡片结构化渲染（当前仅文本摘要）。
- >2000 条消息的深分页。
- 事件乱序缓冲区（按到达序处理 + 去重已覆盖主要风险）。
- `(emj)`/`:emoji:` 表情渲染（需平台 emoji 映射表，成本高收益低）。
