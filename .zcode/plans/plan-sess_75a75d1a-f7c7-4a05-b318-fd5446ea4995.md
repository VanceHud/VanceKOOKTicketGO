# 优化 AI 自动回复：决策契约 + 反幻觉护栏

## 目标症状（已确认）
1. **每条消息都回**——用户发「好的」「谢谢」AI 也照回，很机械
2. **答非所问 / 编造**——回复跑偏或捏造政策

服务商为 DeepSeek（完整支持 JSON mode，可放心开启）。

## 方案概览

### 1. 回复契约升级：让模型自己决定「回不回」（核心改动）

当前每次防抖触发都无条件生成并发送回复。改为让模型在同一个 JSON 输出里先表态：

```json
{"action": "reply" | "silent" | "escalate", "reply": "...", "suggested_type": "...", "type_reason": "..."}
```

- `reply`：正常回复（现状）
- `silent`：用户消息不需要回应（道谢、确认、表情、寒暄收尾）→ **不发送任何消息**，仅记录日志
- `escalate`：模型判断无法依据对话与知识示例确定答案 → 发送兜底话术（模型给的 reply，缺省用「这个问题我需要转交人工客服处理，请稍等」）+ 尾注，然后**转为 takeover 状态**（与现有 MaxReplies 超限的处理一致，可被 `/tkai on` 恢复），避免 AI 连续瞎答

涉及文件：
- `internal/ai/prompt.go`：`replyJSON` 增加 `action` 字段；服务层统一追加「输出协议」段落（说明三种 action 的语义与使用条件），与知识示例一样不经过管理员可编辑模板，防止模板改坏契约；分类指令并入同一协议块
- `internal/ai/prompt.go:40-46`：回复请求**始终开启 JSONMode**（DeepSeek 兼容；`parseReplyJSON` 的容错兜底保留——非 JSON 输出仍按纯文本回复处理，action 缺省视为 reply，主链路不中断）
- `internal/ai/reply.go:240-275`：按 action 分支处理 silent（跳过发送）/ escalate（发送 + `setAIState(takeover)`）/ reply（现状逻辑不变）

### 2. 默认提示词改写（反编造）

`internal/store/repo_ai.go:56` 的 `DefaultAISystemPrompt` 改写，强化：
- 只依据对话内容与参考示例回答；示例与当前问题不相关时**必须忽略示例**
- 无法确定时选择 escalate，**严禁**猜测政策、时间、金额、承诺
- 不需要回应的闲聊选择 silent

存量迁移：`Config()` 读取时若库存值等于旧默认文案（管理员从未自定义过、只是 WebUI 保存时落库了旧默认值），自动替换为新默认；管理员自定义过的提示词不受影响（保留旧常量做比对）。

### 3. 知识检索相关度门槛（治答非所问）

当前 `knowledge.go:161-167` 只要 score > 0 就注入 TopK，关键词模式下「常见词偶然命中」和向量模式下低相似度条目都会被塞进提示词，诱导模型套用不相关答案。

- 关键词模式：要求命中词覆盖率 ≥ 50%（命中词数 / 查询词数，至少 1 个），过滤零散偶然命中
- 向量模式：余弦相似度阈值 0.75（常量，注释标注可按 embedding 模型调整）
- 知识示例的提示语补一句「仅当示例与用户当前问题确实相关时才参考」

### 4. 默认值微调（仅影响新装 / 未自定义的实例）

- `DefaultAIQuietSeconds` 5 → 8 秒：减少用户分多条发消息时 AI 抢话
- `DefaultAITemperature` 0.7 → 0.4：客服场景要确定性，降低发散与编造

### 5. 测试

- `internal/ai/`：新契约的请求组装（协议块、JSONMode 常开）、`parseReplyJSON` 对 action 的解析（silent / escalate / 缺省 / 非 JSON 兜底）、关键词与向量检索的阈值过滤
- 回复流程：silent 不发送、escalate 发送后转 takeover（沿用现有 fake sender/store 测试风格）
- 运行 `go test ./...` 全量验证

## 明确不做

- 不新增设置项（阈值先用常量，避免 WebUI 设置页连带改动；如后续需要可调再暴露）
- 不改动知识捕获、摘要、分类独立调用、WebUI 页面的现有行为
